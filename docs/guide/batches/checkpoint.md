# Закладка: пачка, которая не переделывает сделанное

Одна задача - одна единица работы, но её payload может описывать составную работу: 50 доменов на
одну аренду дефицитного аккаунта, несколько шагов регистрации, 200 строк одного файла. Если такая
задача дошла до 30-го элемента и воркер умер, новая попытка получит тот же payload - и без
закладки начнёт с первого.

**Закладка** (`checkpoint`) - это число: сколько элементов или шагов этой задачи уже сделано.
Задача читает его на входе и двигает после каждого элемента - в той же транзакции, которой пишет
результат элемента.

| Термин | Что это |
|---|---|
| задача (item) | один вызов, одна строка учёта, неизменяемый payload |
| элемент | часть payload, о которой знает только ваш код: один домен из 50, один шаг |
| закладка | `position`: сколько элементов или шагов сделано |

## Рецепт

<!-- tallyho-noexec: фрагмент приложения: lease_account и save_verdict принадлежат вашему проекту -->
```python
from tallyho import Ok, item


@fq.task(queue="checks", max_retries=5)
async def check_domain_chunk(run_id: str, domains: list[str]) -> Ok:
    work = item.require()  # единица работы этой попытки
    start = work.checkpoint() or 0  # 0 на первой попытке, 30 после падения на 31-м
    async with lease_account() as account:
        for index in range(start, len(domains)):
            verdict = await account.check(domains[index])
            async with sessions.begin() as session:
                await save_verdict(session, run_id, verdict)  # результат элемента
                await work.checkpoint_in(session, index + 1)  # и закладка - одним коммитом
    return Ok("chunk", result={"checked": len(domains) - start})
```

Что здесь происходит:

* `item.require()` возвращает `WorkItem` - ту же единицу работы, что `item.current()`, но вне
  задачи бросает `ConfigurationError` вместо тихого `None`. В слоистом приложении этот объект
  удобно [получать из контейнера](../../integrations/dishka.md), а не из фасада.
* `work.checkpoint()` не обращается к базе: значение прочитано тем же запросом, которым задача
  была захвачена.
* `await work.checkpoint_in(session, position)` пишет закладку **только** в вашей транзакции.
  Записи «просто так», вне транзакции, нет намеренно: иначе закладка и ваши данные могли бы
  разойтись.
* `position` - сколько элементов сделано, то есть индекс следующего. Запись монотонна: меньшее
  значение строку не меняет.

## Что это даёт

Результат элемента и закладка живут в одной базе и коммитятся вместе. Поэтому для работы, которая
пишет только в эту базу, повтор не переделывает сделанное: либо есть и результат, и закладка, либо
нет ни того, ни другого.

| Событие | Что с закладкой |
|---|---|
| `Defer` (ресурс кончился) | сохраняется: новая попытка продолжит с того же места |
| ретрай брокера, падение воркера, истёкшая аренда | сохраняется |
| `await th.aclose()` | сохраняется |
| итог `Ok` / `Skip`, отмена батча | строка удаляется в той же транзакции, что итог |
| итог `Error` | сохраняется до истечения `retention`, поэтому `retry_failed()` продолжает, а не начинает заново |
| `retention` дерева | удаляется вместе с деревом |

Закладка заодно двигает видимый прогресс: `handle.in_flight()` показывает «30 из N» без отдельного
`item.progress`.

:::{warning}
Закладка отвечает только за работу, которая пишет в ту же базу. Если внешнее действие уже
выполнено (HTTP-запрос, письмо, списание), а транзакция с закладкой не закоммитилась, повтор
выполнит его снова. Для таких действий нужен ключ идемпотентности на стороне самого ресурса -
закладка его не заменяет.
:::

## Чужая попытка и откат

Закладку пишет только та попытка, которой сейчас принадлежит задача. Если аренда перехвачена (ваш
воркер завис, задачу подобрал другой), `checkpoint_in` бросает `LeaseLostError` - [как и
`complete_in`](../hooks/complete-in.md#если-задача-потеряла-аренду). Исключение должно выйти из
вашей транзакции, чтобы та откатилась: писать результаты элементов от имени чужой попытки нельзя.

Откат вашей транзакции откатывает и закладку, и видимый прогресс: `work.checkpoint()` после
отката возвращает прежнее значение.

## Сколько элементов на одну запись

Запись закладки - один upsert узкой строки внутри уже открытой транзакции; `th_item` она не
трогает. Для очень больших пачек её пишут раз в N элементов: тогда цена повтора - не больше N
элементов работы.

<!-- tallyho-noexec: фрагмент приложения: обработка элемента принадлежит вашему проекту -->
```python
BATCH = 10

for index in range(start, len(rows)):
    await handle_row(rows[index])
    if (index + 1) % BATCH == 0 or index + 1 == len(rows):
        async with sessions.begin() as session:
            await work.checkpoint_in(session, index + 1)
```

Курсор чужого API закладкой не выражается: она хранит число. Если «докуда дошли» - это
непрозрачный токен следующей страницы, порождайте следующую задачу
[`item.spawn`](pipelines.md#spawn-задачи-порождают-задачи): следующая страница - следующая задача.
