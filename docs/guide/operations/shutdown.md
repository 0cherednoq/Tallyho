# Корректная остановка

У tallyho в каждом процессе есть фоновая работа: отправка в брокер, групповая запись итогов
задач, продление аренды, финализация после коммита. `await th.aclose()` доводит её до конца и
останавливает. Вызывайте его при остановке каждого процесса, после того как процесс перестал
принимать работу: HTTP-сервер остановлен, воркер брокера дождался своих задач.

Что делает `aclose`:

1. перестаёт принимать новую фоновую работу и просит остановиться `th.maintenance().run()`;
2. дожидается финализаций, начатых после коммита (`seal`, `cancel`, `retry_failed`);
3. дописывает итоги задач, которые воркер уже принял, а задачи, которые ещё выполнялись,
   сразу возвращает в очередь: аренда снимается, попытка не тратится. Их выполнит другой
   воркер, не дожидаясь `lease_ttl`;
4. останавливает отправку в брокер, дав завершиться начатой.

На всё отведён `close_timeout` (10 секунд). Если процесс не уложился - завис хук, недоступна
база, не отвечает брокер, - оставшаяся работа отменяется, а `aclose` пишет предупреждение в лог и
возвращает управление, не бросая исключения. Потерь при этом нет, восстановление просто
становится медленнее: финализацию подберёт maintenance через `finalize_grace`, аренда истечёт
через `lease_ttl`, сообщение вернётся в очередь отправки через `relay_claim_ttl`. Закладывайте
`close_timeout` в срок, который оркестратор даёт процессу на остановку
(`terminationGracePeriodSeconds`), вместе со временем остановки сервера или воркера.

| Процесс | Порядок остановки |
|---|---|
| API с maintenance в lifespan | остановить приём запросов; `runner.stop()` и `await task`; `await th.aclose()`; закрыть адаптер; `await engine.dispose()` |
| Отдельный maintenance | `serve_maintenance(...)` возвращается по сигналу; `await th.aclose()`; закрыть адаптер |
| Воркер flexiq | `queue.run_worker(...)` возвращается по сигналу; `asyncio.run(th.aclose())`; для долгих задач - вариант со своим сроком, см. [Адаптер flexiq](../flexiq.md#остановка) |
| Тест | `await th.aclose()` до удаления схемы - см. [Тестирование](../testing.md) |

`aclose` можно вызывать из любого event loop: то, что работало в другом loop (так устроен воркер
flexiq), он закроет там же. Повторный вызов ничего не делает.

После закрытия установка не перезапускается. `th.batch(...)`, операции над батчем
(`pause`, `resume`, `cancel`, `reschedule`, `retry_failed`, `retry_finalize`, `release`) и
`th.maintenance()` бросают `ClosedError`; чтение (`view`, `watch`, `wait`, `items`, `find`,
`list_batches`) работает. Транзакция, начатая до закрытия, коммитится как обычно: её задачи
отправит другой процесс, финализацию выполнит maintenance.

Без `aclose` процесс бросает фоновую работу посреди пути. Данные остаются согласованными, но
задачи остановленного воркера ждут `lease_ttl`, прежде чем их выполнит другой воркер, а в логе
появляется `Task was destroyed but it is pending`.
